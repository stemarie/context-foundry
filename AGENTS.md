# Repository instructions

## Delivery

The repository owner has explicitly chosen direct commits to `main`. For authorized changes, complete implementation and verification, then commit and push directly to the default branch. Do not create pull requests or introduce a PR approval gate.

Preserve intervening work and use non-force fast-forward updates with an expected-head check. If the branch advances, inspect and reconcile it before delivery. Direct delivery does not grant production deployment, destructive-action, or credential authority.

GitHub issues are historical delivery/cancellation records, created after the outcome and linked to its commits. They are not the live work queue. AI.Contract owns project contracts and execution state.
