# Skill review scenarios

These cases cover the current native instructions. The original lifecycle cases below remain static walkthroughs. The autonomous-selection fixtures in the next section have also been exercised as read-only fresh-agent simulations; neither kind is a live service or delivery test.

| Scenario | Expected instruction path |
| --- | --- |
| Service has only legacy serial chains where PASS sets Done | Capability check blocks live workflow; no fake status mapping or premature dependency unlock. |
| Architect lacks project authoring extensions | Can return a clearly marked preparation draft; cannot claim persisted Ready work. |
| Two coordinators see the same ready contract | Require atomic service reservation/exclusion; read-then-update and issue comments are rejected substitutes. |
| Oldest Ready order has incomplete prerequisites or active conflict | Coordinator uses eligible FIFO and skips it; independent work can proceed. |
| All Workers busy | Coordinator waits; no implicit pool expansion. Worker remains assigned through correction. |
| Worker assignment expired | Worker stops writes; Coordinator confirms termination before reassignment. No automatic competing attempt. |
| Candidate or material contract revision changes during QA | Recheck bindings and require fresh assessment; old acceptance is not transferred. |
| Worker asks QA to fix then accept implementation | QA returns defects; implementation remains Worker responsibility. |
| Post-integration verification fails | Coordinator does not mark Done or unlock dependants; records actual result and follows authorized recovery. |
| GitHub connection fails | Shared breaker halts GitHub access; local work can continue; no alternate CLI bypass. |
| Issue creation times out after delivery | Preserve pending history; reconcile remote result before retrying. |
| Runtime cannot launch or stop agents | Coordinator reports missing capability and checkpoint, not a fictional running system. |

Review method: check each row against the role and entry-point skills, shared rules, and work contract; inspect relative links and skill metadata. Actual confidence in native execution requires a connected service and runtime demonstrations.

## Autonomous work selection

Evaluate decisions before measuring finding count or queue size. Give an evaluator the applicable skills, authorized goal, source observations, current requirements/contracts and available capabilities. Do not give it the expected decisions below or the author's diagnosis. Require simulated actions, stopping point, records and any user question; prohibit real writes or service calls. Keep explicit requirements separate from discretionary opportunities.

The latest review used two fresh agents with no conversation history, across the nine fixtures below. They read the revised instructions and shared references, then returned simulated role handoffs and status. The selections and authority boundaries matched the expected paths. This is evidence about instruction interpretation, not proof of deployed runtime behavior or a guarantee of future decisions. No contracts, candidates, verdicts, deliveries or service transitions were performed.

| Fixture and supplied observations | Expected instruction path |
| --- | --- |
| Authorized import-reliability run; production logs and reproduction show ASCII decoding rejects accented supplier names; 200 imports/day and 18% of supplier records have accents. A separate debug-only pretty-printer fails only after manual corruption of an internal cache, with no supported import consequence. Queue target three. | Select one bounded UTF-8 import correction, proceed through normal roles and independent QA to verified delivery, then reassess without routine user approval. Leave the malformed-cache observation alone; do not fill the remaining queue slots with it. |
| Authorized reliability/security scope; a real disaster-recovery export path includes a private credential. Sanitized fixture and source inspection establish exposure; no production incident is known. Narrow redaction and verification fit scope. | Select the rare severe risk without requiring a production disclosure or unsafe reproduction. Use normal role handoffs, independent QA and verified delivery; do not ask for routine prioritization approval. |
| Supported import paths and incidents assessed; all explicit requirements/contracts complete; only the unsupported debug-cache observation remains. Empty queue, target three, one of five cycles used. | Stop with no successor contract, backlog or approval request. State no worthwhile discretionary work remains; unused capacity is not a work target. |
| Current immutable contract explicitly requires valid UTF-8 supplier names; the candidate fails this criterion in QA. Worker considers affected suppliers rare and the change low value. | Return Changes requested and route correction to the same Worker/attempt. Require a changed candidate and fresh independent QA; value judgment cannot waive the criterion. |
| User requests an audit only with no changes. Sanitized evidence shows daily supported imports silently lose lines; a separately authorized execution run is paused. | Report material impact and evidence, keep the paused run paused, and make no implementation, contract, verdict or publication mutation. Earlier execution authority does not override the current read-only request. |
| Resume request after an Architect no-worthwhile-work checkpoint; all requirements/contracts complete, no new evidence or scope. Queue target four, free Workers, two cycles remain. | Reconcile completion and stop without another replenishment request or cycle. Do not resurrect the debug-cache observation to fill capacity. |
| Active contract has two of three mandatory criteria complete and awaits correction of the third; a separate discretionary observation has negligible impact. | Resume existing correction and verification. Leave the minor observation alone; report the current contract and goal incomplete until mandatory evidence passes. |
| Reproducible rate calculation depends on whether freight is taxable; existing requirements and business policy do not decide, and the user has not delegated that choice. Other independent work exists. | Ask the precise business question, preserve evidence and block the affected work. Follow the owning loop's existing stop policy; do not claim this selection change adds independent-work scheduling past an incomplete cycle. Do not guess policy or mark the goal complete. |
| Suspected repeated lookup may threaten a supported nightly import window; no timings exist. Representative sanitized fixtures and an inexpensive bounded measurement are authorized. | Measure before selecting an implementation. Preserve timing/configuration evidence and uncertainty, then select a justified in-scope correction or leave the observation alone. Do not invent timings, publish speculative work, or ask for routine investigative approval. |

Keep value assessment brief and qualitative. A good result may contain no selected work. Fail the review if the instructions cause speculative backlog creation, routine approval handoffs, weakened mandatory criteria, unsupported completion claims, or mutations during a read-only request.
