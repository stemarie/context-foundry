# OpenSpec adapter for Foundry

[foundry-start](../foundry-start/SKILL.md) owns repetition/limits; [foundry-loop](../foundry-loop/SKILL.md) owns one native cycle. AI.Contract owns contracts, revisions, reservations, attempts, candidates and lifecycle. OpenSpec owns requirements, design and task tracking. GitHub issues are historical delivery/cancellation records. Editing or installing this adapter starts no work.

Resolve the implementation repository and selected OpenSpec change/store from the user, checkout and CLI evidence. Read AGENTS.md and current source. Require the actual available CLI and schema-defined prerequisites: use context/list/status/instructions commands supported by that version, including the selected store where applicable. A tasks file alone is not readiness. Do not initialize an unrelated directory; perform project setup only when requested.

Planning requests use the installed OpenSpec explore/propose/update workflows and stop with their schema artifacts. They do not reserve work, launch agents or publish an execution issue. Keep settled requirements in main specs and proposed deltas in changes; preserve stable task/scenario IDs and approved decisions.

For execution, reconcile current native jobs/history, source and delivery before each cycle. Map the next coherent outcome into an Architect-authored milestone contract/native revision within the planning horizon. Include specification revision, task/scenario references, design constraints, actual prerequisites/conflicts, acceptance and safety bounds. Reuse the current native order before a successor. An uncertain association creation is reconciled through supported reads, not blindly repeated.

Use a compact mapping in the existing task artifact when helpful:

| Package/task IDs | Requirement/scenario | Project/contract/revision | Evidence and delivery |
| --- | --- | --- | --- |

Carry this mapping through Worker implementation and independent QA. Check only fully demonstrated tasks; distinguish locally verified behavior from accepted/delivered/native Done. Correct unsupported marks on failed audits. Structural validation proves format, not software behavior. Validate through the installed CLI with selected store scope; do not rewrite requirements to justify a shortcut.

Coordinator records integration/completion only after exact-candidate QA, authorized repository delivery, remote identity and successful postchecks. Publish historical issues after outcome and link them as evidence; neither issue closure nor OpenSpec checkboxes dispatch work or replace native state. Preserve independent implementation/planning repository permissions and revisions when stores live elsewhere.

Stop on overall approved requirement completion, unresolved authority/prerequisite or the owning loop's limit. Do not invoke openspec-apply-change as another executor inside a Foundry cycle, create a shadow queue, archive incomplete changes or add deferred product scope.
