# Foundry Start

Own the outer repetition around [foundry-loop](../foundry-loop/SKILL.md). Resolve the concrete goal, repository, AI.Contract connection/project, milestone horizon, pools, runtime adapters and completion evidence. Read applicable AGENTS.md and [operating rules](../OPERATING_RULES.md). Keep AI.Contract authoritative for live work; GitHub issues record final outcomes only.

Use at most five cycles unless the user supplies another limit. Count a cycle when it starts and preserve its count across interruption/resume. A limit is a ceiling, not a work target. Carry the user's exclusions, repair policy and authorization throughout. Default to stopping on a failed required gate or unresolved blocker; an explicit recoverable-error policy permits routine repair within the active stage. Expected passing negative tests are not failures.

For a named or clearly established OpenSpec change, read [openspec-foundry](../openspec-foundry/SKILL.md), reconcile its schema prerequisites and mapped requirements/tasks, and retain the selected store. Do not invent a change or initialize an unrelated project. Without OpenSpec, use the same native workflow with the current authoritative specification.

Before every cycle, inspect actual implementation/delivery and native jobs/history. Stop if the goal is already fulfilled. Resume incomplete existing work before authoring a successor. Ask Architect only for the next coherent necessary outcome within the human horizon; avoid duplicate replenishment and speculative hardening.

Run one foundry-loop cycle and require actual native completion plus verified delivery/history before continuing. QA corrections remain within the same cycle; a material scope/revision decision returns to Architect. Reconcile uncertain launch, submission and remote outcomes before any repeat. A busy pool means wait; unknown execution or missing runtime/credentials means report the prerequisite, not invent actors or an issue queue.

After a successful cycle, record project/contract/revision/attempt, evidence, target and historical record, then reassess remaining scope. Stop on success, limit, no progress, missing dependency or a genuine product/authority decision. Do not schedule a future run, create a daemon or increase scope/limit without instruction.

An explicit run request authorizes the bounded cycles within existing project/repository permissions, including final historical publication after outcome. It does not itself grant credential, production, deployment or unrelated communication authority. Installation/editing this skill starts no work.

Report achieved/remaining goal, cycles used, actual last stage, verification, native bindings and delivery/history references.
