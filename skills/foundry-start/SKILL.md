# Foundry Start

Apply [request routing](../ROUTING.md): "continue" retains the established workflow/stage. Use this outer run for authorized native delivery; a current Worker assignment uses `foundry-implement`. Missing service/runtime access remains a prerequisite, never an alternate executor.

Own the outer repetition around [foundry-loop](../foundry-loop/SKILL.md). Resolve the concrete goal, repository, AI.Contract connection/project, milestone horizon, pools, runtime adapters and completion evidence. Read applicable AGENTS.md and [operating rules](../OPERATING_RULES.md). Keep AI.Contract authoritative for live work; GitHub issues record final outcomes only.

Use at most five cycles unless the user supplies another limit. Count a cycle when it starts and preserve its count across interruption/resume. A limit is a ceiling, not a work target. Carry the user's exclusions, repair/stop policy and authorization throughout. Apply the operating rules' repair and stop decisions: ordinary in-scope failures trigger diagnosis, correction and verification within the current cycle without a separate repair approval. Failed gates still block dependent transitions. Respect stricter user stop instructions and runtime limits. Expected passing negative tests are not failures.

For a named or clearly established OpenSpec change, read [openspec-foundry](../openspec-foundry/SKILL.md), reconcile its schema prerequisites and mapped requirements/tasks, and retain the selected store. Do not invent a change or initialize an unrelated project. Without OpenSpec, use the same native workflow with the current authoritative specification.

Before every cycle, inspect actual implementation/delivery and native jobs/history. Stop if the goal is already fulfilled. Resume incomplete existing work before authoring a successor. Ask Architect only for the next coherent necessary outcome within the human horizon, applying the operating rules' autonomous work selection. Proceed with material in-scope work through normal role handoffs without a routine prioritization approval. Leave low-value observations alone; avoid duplicate replenishment and speculative hardening.

When no worthwhile discretionary work remains, stop without filling the cycle limit or generating a backlog, and briefly report what was achieved and any remaining limitation. Preserve unfinished explicit requirements and active contracts; an unmet goal or blocker is not completion. Ask the user only for genuine unresolved product decisions or missing authority, and report unavailable capabilities with the concrete prerequisite.

Run one foundry-loop cycle and require actual native completion plus verified delivery/history before continuing. QA corrections remain within the same cycle; a material scope/revision decision returns to Architect. Reconcile uncertain launch, submission and remote outcomes before any repeat. A busy pool means wait; unknown execution or missing runtime/credentials means report the prerequisite, not invent actors or an issue queue.

After a successful cycle, record project/contract/revision/attempt, evidence, target and historical record, then reassess remaining scope. An unsuccessful repair triggers a useful next diagnostic or changed approach; repeated failure without progress requires reassessment before more attempts. Stop on success, an explicit limit/stop instruction, a concrete blocker with no useful authorized next action, or a genuine unresolved product/authority decision. Return a truthful checkpoint for incomplete work. Do not schedule a future run, create a daemon or increase scope/limit without instruction.

An explicit run request authorizes the bounded cycles within existing project/repository permissions, including final historical publication after outcome. It does not itself grant credential, production, deployment or unrelated communication authority. Installation/editing this skill starts no work.

Report achieved/remaining goal, cycles used, actual last stage, verification, native bindings and delivery/history references.
