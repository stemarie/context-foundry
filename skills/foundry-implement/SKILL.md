# Foundry Implement

Apply [request routing](../ROUTING.md) and verify the current native assignment. For a native run without an assignment, Coordinator through `foundry-start` owns reservation/launch; do not self-claim or switch to another executor. Ordinary implementation outside native Foundry follows the selected project's workflow.

Read [Worker](../foundry-worker/SKILL.md), the [native interface](../AI_CONTRACT_INTERFACE.md) and [operating rules](../OPERATING_RULES.md). Resolve the project/contract from the request and current service state. An old issue number alone supplies no native attempt or permission to execute.

Require an actor-bound assignment, supported runtime/workspace adapter and current semantic version plus complete native executable revision. Coordinator reserves/launches; this skill does not self-claim or fabricate those prerequisites. Verify repository identity, base, branch, applicable AGENTS.md, current revision/digest/attempt and scope before changing files. Preserve intervening/unrelated work.

Trace reported defects to actionable implementation/configuration/runtime causes. Implement only the authorized outcome, run meaningful required checks and inspect the candidate diff. Label hypotheses, failures and skipped checks accurately. Under the shared repair rules, ordinary in-scope implementation/setup/test failures trigger correction and relevant rechecks without a separate repair approval. Keep failed gates closed, preserve current role/attempt and explicit limits, and reassess repeated failures using evidence. Material requirement conflicts return to Architect through Coordinator.

Submit an immutable local candidate through `workflow_submit` with actual check evidence and current bindings. Reconcile uncertain submission using the durable prepared intent/SHA; never create an empty second commit or infer acceptance from a local receipt. Stay assigned through QA corrections and require fresh QA for changed candidates.

Do not self-approve, integrate, mark Done, publish historical issues or deploy. Return the service candidate/attempt/revision, verification evidence and actual stage. OpenSpec checkboxes describe demonstrated work; they do not replace native ownership or completion.
